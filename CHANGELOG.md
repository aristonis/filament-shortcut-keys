# Changelog

All notable changes to `filament-shortcut-keys` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

**Assistive technology hears the shortcut.** A control that carries a key badge now also carries
`aria-keyshortcuts`, so a screen reader announces the key with the control. `G` sequences are left
out because the attribute cannot express a sequence; the cheatsheet lists them. A value the host app
set on the control is never overwritten.

### Changed

**Default keys no longer hold `Alt`.** Navigation and custom bindings now use a leader key, `G` then
a letter, and header actions use bare letters. `Alt`+letter clashed with the browser (`Alt`+`D` for
the address bar, `Alt`+`F` for its menu), `Alt`+`Shift` is the Windows keyboard-layout switch, and on a
Mac `Option`+letter types a character, so a shortcut could fire while typing. A page cannot tell which
combinations the browser, the OS or the layout own; a bare key pressed on the page always reaches it.
`G` waits about a second and a half for its letter, `Esc` cancels, and its badges appear only while it
waits. Held modifiers are still available per set through the `modifiers` config, which now also
accepts a single letter as a leader key. Changing that config now refreshes the cached keymap at
once instead of after the cache lifetime.

Upgrading: a config file published from an earlier build still lists `['alt', 'shift']` and `['alt']`
and keeps those keys. Delete the `modifiers` entries, or republish the config, to take the new
defaults.

**Header actions are only keyed when a stray press is harmless.** With actions on bare letters, one
accidental keystroke could run an action that does its work on the click. On bare letters such an
action now gets no default key; actions that open a page, a modal or a confirmation keep theirs. A letter pinned in the
`overlay` config still keys an instant action on purpose.

**Laravel 11 is no longer supported.** Composer refuses every Laravel 11 release over unpatched
security advisories, and its security support has ended. The package now requires Laravel 12 or newer.

**Single-key shortcuts can be switched off.** The cheatsheet has a switch that silences every bare key
and `G` sequence in that browser, for people using assistive technology or voice control. Held-modifier
shortcuts keep working.

### Fixed

**Key badges and announcements survive Livewire updates.** Any Livewire request on a page, such as
opening and closing a modal, re-rendered the markup and stripped every key badge and
`aria-keyshortcuts`; they only came back after navigating away. The script now repaints them after
each in-page update.

**A key pressed right after a shortcut opens a modal waits for that modal.** A confirm or edit modal
only appears once its Livewire request returns, so `Enter` pressed straight after `Delete` reached the
row behind it and opened its edit page. Keys without a modifier now wait for the response a shortcut
started, for up to two seconds.

**Actions that render as links are reachable again.** Every keyable control was looked up by
`wire:click="mountAction('name'"`, which an action with a url does not have. Filament gives View, Edit
and Create a url whenever the resource registers that page, so on a resource generated by
`make:filament-resource` the `Enter` key did nothing, `Alt`+letter for Create did nothing, and `view`
could not be registered as a row action at all. Header actions with a url are now handed to the client
as a url to navigate; row actions are found by `wire:key`, which Filament emits on a record action in
either shape.

**The panel no longer fails on the second request under Laravel 13.** The resolved keymap was cached as
an object graph, and Laravel 13 restricts cache unserialization to an allowlist that is empty by
default, so the entry came back as `__PHP_Incomplete_Class`. The map is now cached as plain arrays and
rehydrated on read, which needs no `cache.serializable_classes` entry on any driver.

**A custom binding pointing at a route now shows its key.** The in-place badge was chosen by which set
a shortcut belonged to, and only the navigation set was allowed to badge a link. An admin who bound a
key to a route in the app got a working key with nothing on screen to announce it, leaving the
cheatsheet as the only way to find it. A badge is now decided by how a shortcut fires rather than by
which set it came from, which also covers the header actions that carry a url as of the fix above.

**Table keys no longer act behind a modal or on a focused control.** With a row marked, pressing
`Enter` in Filament's delete confirm ran the row's edit instead of confirming, and `Space` on any
focused button toggled the row's checkbox. Keys without a modifier now stay with whatever owns the
keyboard: an open modal (even one that opened without taking focus), an open select, a dropdown, a
menu or a tab list, and `Enter` or `Space` on a focused button or link. The row cursor now moves
real focus, so `Enter` acts on the marked row rather than on whatever was clicked last. A clicked row
checkbox no longer counts as typing, which had left every table key dead until the next click.

**The arrow keys scroll the page again.** On any page with a table, `↑`/`↓` moved the row cursor and
`←`/`→` changed the table page, so a long page or a wide table could not be scrolled from the
keyboard. The row cursor now starts with `J` (down) or `K` (up) and is released with `Esc`; the arrows
move it and paginate only while it is live, and go back to scrolling once you click elsewhere. While
row actions share the table's modifiers (the default) they are never given `J` or `K`, so a host
whose row action had auto-assigned one of those letters sees it move to the next free letter. The
documented lettering example was wrong and now matches what the code assigns.

**Row keys act on the record you marked.** The row cursor remembered a position, so after a sort, a
search or a polling refresh `Enter`, `Delete` or a custom row action could run on a different record,
with no row visibly marked. The cursor now follows the record itself and is dropped when that record
leaves the table. It also skips the column-search and group-header rows, which it could land on
before.

**One key press runs one action.** Holding a key fired its shortcut again on every auto-repeat, so a
held `Delete` reopened the confirm and a held navigation key queued up visits. A held key now acts
once; only the row cursor keeps moving while an arrow is held. Keys pressed while an input method is
composing text (Arabic, CJK) are ignored, Safari included. If the script ends up loaded twice, or a
newer version loads mid-session, only the newest copy listens.

### Documentation

- The install steps now include `php artisan filament:assets`. Without it no key fires and nothing
  reports an error, which made it the most common first-run failure.
- `rowActions()` documents that the array is ordered data: reordering it reassigns letters.

### Internal

- The browser half of the plugin has tests. `npm test` runs them on node alone, with no install and
  no build step, covering the key dispatcher, the table row cursor, the cheatsheet overlay, the key
  hints and keymap parsing. Every module the client ships was previously unexercised, which is how a
  hint could stop being painted without anything going red.
- The cache regression test runs on every supported Laravel version. It built its fixture from an
  `ArrayStore` constructor argument that only exists from the middle of 12.x onward, which fataled on
  18 of the 32 matrix jobs. The fixture now states the behaviour it needs, a store that refuses to
  hydrate classes, instead of borrowing a framework class to get it.
- `composer test` runs without a coverage driver installed. `composer test:coverage` produces the
  report for anyone running pcov or Xdebug.

## [1.0.0] - 2026-09-01

First release. Keyboard shortcuts for a Filament panel, derived from what the panel already declares.

### Added

**Shortcuts without configuration.** Navigation shortcuts are built from every registered resource
and page, header actions from each page's own action list, and table keys once from a fixed set that
applies to every table in the panel. Adding a resource gives it a shortcut; nothing to register.

**Real controls, real permissions.** A shortcut clicks the Filament control or follows the route you
would have used yourself, so authorization and confirmation modals stay Filament's. The plugin never
invents a privileged action and never calls a Livewire method directly.

**Stable identity.** A shortcut is keyed on the resource class or the action name, never on a slug or
a label, so a stored override survives both renaming and reordering.

**Two modes.** `locked` gives every admin one shared map. `personal` lets each admin customize their
own: the first edit forks the shared map, stores only the differences, and leaves everything else
following the conventions — so a resource added later still appears in a customized map.

**Custom bindings.** An admin can bind a key to a route in the app or to an element already on the
page. Those two shapes are the whole surface, which is what keeps a binding from becoming a way to
reach something you could not otherwise reach.

**Gated authoring of shared maps.** An authority gate you supply, denying by default, can let a
trusted admin create a preset, clone one, or edit a shared map in place. Editing in place asks for
explicit confirmation, because it changes the map for everyone using it.

**Discoverability.** A reference page lists every panel-wide shortcut, and `?` opens a cheatsheet
overlay of what is active on the current page.

**Row actions.** Register your own row-action names once and each gets a stable letter across the
whole panel, active on any table exposing an action of that name, dispatched against the focused row.

**Configuration.** Per-set modifiers, a config overlay that can force a letter or drop a shortcut with
no database rows, the authority gate, and the cache lifetime.

**Maintenance.** `shortcut-keys:prune` removes stored overrides whose target no longer exists. It only
deletes what it can prove is gone, and reports the rest rather than guessing.

**Portability.** Any authenticatable model, keyed by integer, UUID, or ULID. Tested against SQLite,
MySQL, and PostgreSQL on every push.

### Requirements

- PHP 8.2 or newer
- Laravel 12 or newer
- Filament 5.0 or newer
- MySQL 5.7+, MariaDB 10.2+, PostgreSQL, or SQLite (the schema uses a native `json` column)

### Known limitations

- **English only.** Every string is translatable and publishing the language files gets you a fully
  translated panel, but only English ships.
- **Right to left is unproven.** Pagination keys are mirrored for an RTL panel and that mirroring is
  tested, but the experience as a whole has not been verified in a browser.
- **A page cannot declare its own shortcuts.** Shortcuts come from navigation, page actions, and
  tables.
- **Modifiers are chosen per deployment, not per admin.** Configured once for everyone.
- **Customization covers navigation shortcuts.** Table keys and row actions are uniform by design and
  are not remappable.
- **The keymap is public.** It is built from every registered page without a permission check, so it
  reveals which pages exist, not what an admin may do. Access is enforced when the key fires. A page
  whose existence is itself sensitive does not belong in a panel's navigation.
- **Single key combinations only.** No multi-key sequences, and no command palette.
